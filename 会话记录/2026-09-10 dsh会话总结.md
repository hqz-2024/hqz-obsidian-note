## 三、dsh 架构：两个平面

dsh 是全插件化的 Cordis harness，「一个功能放哪里」靠两个平面判断：

- **宿主组合（host composition）**：放注册中心和跨会话共享的东西——持久化、沙箱与审批栈、模型路由、子代理注册表。
- **Agent 预设（agent preset）**：放单个会话贡献给这些注册中心的东西——它的工具、人格、提示词段落。

一条规则：**发布 service 的行属于宿主组合**；只有当预设确实独占该 service、且外面没人读时，才放进 `isolate` realm。判断依据是「能力缝（capability seam）」= Service Definition / Provider / Consumer 三个角色，缺一不可。

> - **GitHub API 限流**（`API rate limit exceeded for 203.10.96.139`）查 `/users/hqz-2024/repos` → 改为解析缓存文件绕过。
> - **改完 `cordis.patch.yml` 后工具消失**（`unknown tool "edit"/"pwsh"/"read"`）→ 重启 dsh web 应用后全部恢复。
