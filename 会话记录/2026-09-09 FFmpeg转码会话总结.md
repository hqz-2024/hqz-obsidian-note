## 三、m4v → MP4：踩的那个坑

源文件是**飞书录制**的 m4v，轨道构成：

| 轨 | 编码 | 说明 |
| --- | --- | --- |
| #0:0 | H.264 High 1920×1080 yuv420p | 视频，MP4 兼容 |
| #0:1 | AAC LC 48kHz stereo 320kbps | 音频，MP4 兼容 |
| #0:2 | unknown / data（`TimeCodeHandler`, timecode 00:00:00:00） | **飞书的时间码数据轨，MP4 容器不支持** |

所以最直观的 `-map 0 -c copy` **直接失败**：

```
Could not find tag for codec none in stream #2, codec not currently supported in container
Could not write header (incorrect codec parameters ?): Invalid argument
EXIT=-22
```

**解决办法**：只保留视频轨 + 音频轨，丢掉那条没用（且不可播放）的时间码轨：

```powershell
ffmpeg -y -hide_banner -i input.m4v -map 0:v:0 -map 0:a:0 -c copy -movflags +faststart output.mp4
```

- `-c copy` = 不重新编码，画质零损失，81 秒的视频几秒就跑完（speed 327x）
- `-movflags +faststart` = 把 moov atom 挪到文件开头，适合网页/微信直接播放

> [!note] 成品里仍会看到一条 data 轨
> MP4 封装会自动生成一条标准的 `tmcd` 时间码元数据轨，播放器会忽略它，属正常现象，不是转换出错。

## 四、压到 10MB 以内：为什么选 480p

用户要求「压到 10MB 以内，分辨率可以降，降到多少合适？」

**结论：854×480（480p），保持 30fps。**

理由是算「每像素分到多少码率」：

| 分辨率 | 每帧码率 | 观感 |
| --- | --- | --- |
| 1920×1080 | 0.013 bit/像素 | 明显发花 |
| 1280×720 | 0.029 bit/像素 | 文字发糊 |
| **854×480** | **0.065 bit/像素** | **干净，手机上够清晰** |

预算算法（十进制 MB）：

```
目标 9.3 MB ≈ 9,300,000 字节
视频码率 ≈ (9,300,000 × 8 / 时长秒) − 音频码率
例：81.8s，(9.3M×8/81.8) − 96k ≈ 800kbps
```

音频统一降到 **AAC 96kbps 立体声**（≈0.96MB，人声够用），剩下的全给视频。

### 可复用的两遍编码命令

```powershell
$ff = 'C:\Users\bestarc\ffmpeg\extracted\ffmpeg-9.0.1-essentials_build\bin\ffmpeg.exe'
# 第一遍：分析
& $ff -y -hide_banner -i $in -map 0:v:0 -vf "scale=854:480:flags=bicubic" `
  -c:v libx264 -b:v 800k -maxrate 1000k -bufsize 1500k `
  -preset slow -profile:v main -level 3.1 -pass 1 -passlogfile $log -an -f mp4 NUL
# 第二遍：出片
& $ff -y -hide_banner -i $in -map 0:v:0 -map 0:a:0 -vf "scale=854:480:flags=bicubic" `
  -c:v libx264 -b:v 800k -maxrate 1000k -bufsize 1500k `
  -preset slow -profile:v main -level 3.1 -pass 2 -passlogfile $log `
  -c:a aac -b:a 96k -movflags +faststart $out
```

**校验**（必做，确认成品能完整解码）：

```powershell
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,codec_name -of csv=p=0 $out
ffmpeg -v error -i $out -f null -      # 打印 DECODE_EXIT=0 才算通过
```

## 六、经验与遗留

> [!important] 这次学到的
> - **飞书录制的 m4v 有时间码 data 轨**，转 MP4 必须显式 `-map 0:v:0 -map 0:a:0`，不能 `-map 0 -c copy`。
> - **「压到 X MB」要先算码率预算再定分辨率**，不能只看分辨率拍脑袋；10MB/80 秒这个量级，480p 是清晰度和体积的平衡点。
> - **两遍编码（2-pass）比恒定质量（CRF）更适合硬性体积上限**，能把码率压在预算内。
> - 出片后一定用 `-f null -` 完整解码校验一次，避免「文件生成了但播不动」。
> - 本机既是 dsh 服务器又是用户机，所以直接用 `pwsh` 工具就能操作本机；只有远程部署时才需要 `sidecar` + `local_run`。
