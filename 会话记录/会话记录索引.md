## 原始会话文件在哪

dsh 把每个会话按「工作区路径」编码成目录名，存在：

```
%USERPROFILE%\.dsh\sessions\<编码后的工作区路径>\<会话 id>\session.v2.jsonl.zstd
```

例如本次 dsh 会话：

```
C:\Users\bestarc\.dsh\sessions\--C-Users-bestarc-Desktop-deepseek-harness--\
  session-31804be7-088b-4ec3-b0fd-a667ea4a0d56\session.v2.jsonl.zstd
```

> [!warning] 它是**多帧拼接**的 zstd，不能直接解
> 文件不是「一整段 zstd」，而是**每个写入批次一个独立 zstd 帧**首尾拼接。
> 用 `zstdDecompressSync` 直接解只会拿到第一帧（例如 2.7MB 的文件只解出 223 字节）。
> 正确做法是按 zstd 帧结构扫描出每帧的字节区间，再逐帧解压（引擎里对应
> `packages/session/session-persistence-jsonl/src/zstd.ts` 的 `scanZstdFrames`）。
> 本次是用一节临时脚本复刻该逻辑后成功解出全部 1576 条事件。

会话状态（标题、token 统计、上下文压力、权限预设）另存在：

```
%USERPROFILE%\.dsh\storages\session_projcache.json 
%USERPROFILE%\.dsh\storages\workspace.json      # 工作区 ↔ 会话 id 的对应表
```

> [!note] 空会话很多
> `.dsh\sessions` 里存在不少只有一行 header（约 336 字节）的空会话——那是点开「新对话」但没发消息留下的。真正有内容的会话可以直接按文件大小筛掉它们。
